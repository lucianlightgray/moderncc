# <flag>|<level>|<reason>   documented overrides of the derived -O ladder
#
# tools/selfhost-optbench.py derives a level for every level-assignable row in
# src/mccopt.h from its own measurements, and --check fails if mccopt.h
# disagrees. Those measurements are INSTRUCTIONS RETIRED. The ladder is no
# longer decided on instructions: it is decided on CPU TIME, measured in
# tests/optfire/leveltime.tsv, and every row below is the CPU-time verdict
# overriding the instruction-derived one. A pin is no longer a debt, it is the
# metric of record; the derivation is kept because it is a second opinion and
# --check is what stops the two drifting apart silently.
#
# The rule the time measurements are read against:
#
#   A row keeps a shipped level only if it makes stage-1 self-compile, stage-2,
#   or a kernel measurably FASTER without making another measurably SLOWER.
#   "Measurably" means outside that measurement's own empirical floor:
#     stage-1 CPU time   +-0.55%  (4 identical configs, 40 interleaved reps)
#     stage-2 CPU time   +-0.43%  (15 configs whose stage-1 object is BYTE
#                                  IDENTICAL to the base, so their true effect
#                                  is exactly zero and the spread is the floor)
#     kernel CPU time    per kernel, measured by linking a padding TU ahead of
#                        the unchanged kernel: interp 34.3%, sieve 32.2%,
#                        loopnest 8.5%, poly 6.3%, divmod 5.6%, strproc 5.1%,
#                        structops 3.3%, branchy 1.8%, nbody 0.8%, mathfun 0.5%
#
# Code layout is why the floors are so wide and why instructions retired are
# still read beside the clock: shifting a kernel's code by a few bytes of
# unrelated padding moves its CPU time by up to a third, so a time delta is
# credited to a flag only when the layout-immune counter agrees with its sign.
#
# --- kept on the shipped ladder, on merit, in CPU time
#
# divmagic is no longer a pin against its own measurement. On the time metric
# it simply passes: divmod runs 28.2% faster with it (n=21 interleaved, divmod
# layout floor 5.6%), which is the largest single effect in the table. It costs
# 0.44% of stage-1 and loses 6.4% on structops and 1.7% on mathfun, which is a
# missing cost model, not a reason to move the row.
divmagic|2|divmod +28.2% cpu time against a 5.6% layout floor; the row now passes on merit, not by exception
# reemit-templates is the one row kept against its own numbers. It is 12.99% of
# stage-1 CPU time -- the single most expensive item in the compiler -- for no
# stage-2 payoff the clock can see. It stays because it is not an optimizer: it
# gates bfold, ident, cprop, cse, dse, sccp, jt and tco, and at level 2 the
# whole -O1 strategy set stops firing (tests/optfire/levels.txt catches it).
# Its measured "gain" is everything downstream of it. The 12.99% is a finding
# about that pipeline, and it is where the next compile-speed work should go.
reemit-templates|1|infrastructure, not an optimizer: gates 8 strategies, and 12.99% of stage-1 cpu time is a finding about the pipeline rather than a level
# reg-color is the row the premise test put BACK. Demoted with the rest, -O2
# stage-2 read 0.52% slower and retired 0.25% more instructions; restoring it
# alone made -O2 stage-2 0.560s against 0.578s reduced and 0.575s before -- 3.1%
# faster than the reduced ladder and 2.6% faster than the ladder it replaces --
# on 0.151% fewer instructions. It was invisible per-flag (-0.12% stage-2, inside
# the 0.43% floor) and unmistakable at level granularity.
reg-color|2|-O2 stage-2 is 3.1% slower without it; the per-flag reading was inside the floor and the level-granularity one is not
# trunc32 is the only row that pays on both workloads at once: divmod +23.2%
# cpu (floor 5.6%, counter +5.39%), structops +3.3%, stage-2 +2.46% cpu on
# +0.125% fewer instructions, and it makes stage-1 0.20% FASTER.
trunc32|1|pays on both workloads and costs nothing: divmod +23.2% cpu, stage-2 +2.46%, stage-1 0.20% faster
# builtin-copysign is inert on the self-host -- its stage-1 object is byte
# identical to the base -- and worth 3.73% of mathfun's cpu time against that
# kernel's 0.51% layout floor, with the counter agreeing (+1.00%). Free and
# positive, so it stays.
builtin-copysign|1|mathfun +3.73% cpu against a 0.51% layout floor, counter agrees, and zero stage-1 cost
# if-conversion-abs earns -O2 on branchy: +2.13% cpu against branchy's 1.76%
# layout floor with the counter agreeing (+3.18%). Thin, and it is the one
# shipped row whose margin is close enough to its floor to be worth re-reading
# if branchy changes.
if-conversion-abs|2|branchy +2.13% cpu against a 1.76% layout floor; the thinnest margin left on the ladder
#
# --- kept because the row is not a performance decision
#
# merge-constants shows 4.55% of stage-1 CPU time and no payoff, which is a
# demotion by the rule. It cannot go: whether identical string and __func__
# constants share storage is observable to a conforming program. Moved off, it
# changed two xoracle verdicts in OPPOSITE directions --
#   gcc.dg/c99-func-3.c         PASS -> DIFF_EXIT (wants abort, got 0)
#   gcc.dg/torture/20240517-1.c PASS -> DIFF_EXIT (wants 0, got abort)
# -- so this row is decided by the oracle set, not by a clock.
merge-constants|2|two xoracle cases change verdict without it; constant sharing is observable semantics, not an optimization
# inline-functions was unmeasurable: the pair -finline with -fno-inline-functions
# was an internal compiler error --
#   mcc -O2 -finline -fno-inline-functions -c src/mcc.c
#   src/mccircap.c:797: internal compiler error: vstack leak (1)
# -- so every configuration that turned it off failed to build. The defect was
# ast_inline_graft pushing a result for an Invoke node typed VT_VOID, which the
# direct-call replay leaves unpushed and the statement level therefore does not
# pop; -fno-inline-functions is the only route to that graft, do_inline being
# `&& !ast_inline_pass_env`. Both configurations build clean now and the row is
# measurable, but it has not been re-measured, so the level does not move yet.
# The measurement, not this pin, is what should decide it next.
inline-functions|2|the -finline -fno-inline-functions ICE is fixed and the row is now measurable; the level is unchanged because it has not yet been re-measured, not because it cannot be
# fmov-imm cannot be measured on this host: ast_fmov_imm_env is compiled to 0
# off arm64, so the gate cannot fire and "no effect" here says nothing about
# where it belongs. Not measured is not the same as measured-no-effect.
fmov-imm|1|ast_fmov_imm_env is compiled out off arm64, so this host cannot measure it either way
# The storeval family's off-state is a deliberately incomplete replay-fidelity

# lowering (docs/TODO.md, the bisection-handle note). Sweeping one off measures
# the handle. Their stage-2 time readings (-1.08%, -1.17%) disagree in sign with
# the counter and are layout.
# storeval-callstore used to ICE alone of the ladder rows at -O3 with

# holds both shapes. Both states of the row build clean; it is measurable and

storeval-constl|1|replay-fidelity bisection handle; its off-state is an incomplete path, not a lowering
storeval-rot|1|replay-fidelity bisection handle; its off-state is an incomplete path, not a lowering
storeval-calllast|1|replay-fidelity bisection handle; inert here, stage-1 object byte identical to the base

# --- rung 10: measured a PESSIMIZATION

# builtin-math is one knob over two lowerings, one excellent and one broken.
# fabs is spilled to the stack, sign-cleared with a BYTE store into the middle
# of it and reloaded whole -- a store-to-load-forwarding stall on every call:
#     movq %xmm0,-0x10(%rbp) ; andb $0x7f,-0x9(%rbp) ; movq -0x10(%rbp),%xmm0
# mathfun is 83.5% SLOWER with the fold on against a 0.51% layout floor, and
# branchy 45.5% slower against 1.76%. The sqrt inline on the same knob is worth
# +11.2% on nbody against a 0.82% floor, and demoting costs that. The fix is
# two things: andpd against a sign mask held in a register, and splitting the
# fabs lowering off this row so the sqrt half can ship without it.
# The -ffast-math contract is NOT the blocker it was: it is separable and now
# separated. -ffast-math sets optflag[BUILTIN_MATH] directly (src/libmcc.c), so
# cli/fast_math_implies_no_math_errno still reads plain=1 fast=0 off=1 with the
# default level at 10.
builtin-math|10|mathfun -83.5% and branchy -45.5% cpu against 0.51% and 1.76% layout floors; the fabs lowering is a store-forwarding stall
builtin-math-prepass|10|masked by builtin-math -- ast_math_inline_run returns 0 without it -- so it cannot fire below the rung that one sits on
