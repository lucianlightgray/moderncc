# <flag>|<level>|<reason>   documented overrides of the derived -O ladder
#
# tools/selfhost-optbench.py derives a level for every level-assignable row in
# src/mccopt.h from its own measurements, and --check fails if mccopt.h
# disagrees. Those measurements are INSTRUCTIONS RETIRED. The ladder is no
# longer decided on instructions: it is decided on CPU TIME, measured in
# tests/optfire/leveltime.tsv, and every row below is the CPU-time verdict
# overriding the instruction-derived one. A pin is no longer a debt, it is the
# metric of record; the derivation is kept because it is a second opinion and
# --check is what stops the two drifting apart silently.
#
# The rule the time measurements are read against:
#
#   A row keeps a shipped level only if it makes stage-1 self-compile, stage-2,
#   or a kernel measurably FASTER without making another measurably SLOWER.
#   "Measurably" means outside that measurement's own empirical floor:
#     stage-1 CPU time   +-0.55%  (4 identical configs, 40 interleaved reps)
#     stage-2 CPU time   +-0.43%  (15 configs whose stage-1 object is BYTE
#                                  IDENTICAL to the base, so their true effect
#                                  is exactly zero and the spread is the floor)
#     kernel CPU time    per kernel, measured by linking a padding TU ahead of
#                        the unchanged kernel: interp 34.3%, sieve 32.2%,
#                        loopnest 8.5%, poly 6.3%, divmod 5.6%, strproc 5.1%,
#                        structops 3.3%, branchy 1.8%, nbody 0.8%, mathfun 0.5%
#
# Code layout is why the floors are so wide and why instructions retired are
# still read beside the clock: shifting a kernel's code by a few bytes of
# unrelated padding moves its CPU time by up to a third, so a time delta is
# credited to a flag only when the layout-immune counter agrees with its sign.
#
# --- kept on the shipped ladder, on merit, in CPU time
#
# divmagic is no longer a pin against its own measurement. On the time metric
# it simply passes: divmod runs 28.2% faster with it (n=21 interleaved, divmod
# layout floor 5.6%), which is the largest single effect in the table. It costs
# 0.44% of stage-1 and loses 6.4% on structops and 1.7% on mathfun, which is a
# missing cost model, not a reason to move the row.
divmagic|2|divmod +28.2% cpu time against a 5.6% layout floor; the row now passes on merit, not by exception
# reemit-templates is the one row kept against its own numbers. It is 12.99% of
# stage-1 CPU time -- the single most expensive item in the compiler -- for no
# stage-2 payoff the clock can see. It stays because it is not an optimizer: it
# gates bfold, ident, cprop, cse, dse, sccp, jt and tco, and at level 2 the
# whole -O1 strategy set stops firing (tests/optfire/levels.txt catches it).
# Its measured "gain" is everything downstream of it. The 12.99% is a finding
# about that pipeline, and it is where the next compile-speed work should go.
reemit-templates|1|infrastructure, not an optimizer: gates 8 strategies, and 12.99% of stage-1 cpu time is a finding about the pipeline rather than a level
# reg-color is the row the premise test put BACK. Demoted with the rest, -O2
# stage-2 read 0.52% slower and retired 0.25% more instructions; restoring it
# alone made -O2 stage-2 0.560s against 0.578s reduced and 0.575s before -- 3.1%
# faster than the reduced ladder and 2.6% faster than the ladder it replaces --
# on 0.151% fewer instructions. It was invisible per-flag (-0.12% stage-2, inside
# the 0.43% floor) and unmistakable at level granularity.
reg-color|2|-O2 stage-2 is 3.1% slower without it; the per-flag reading was inside the floor and the level-granularity one is not
# trunc32 is the only row that pays on both workloads at once: divmod +23.2%
# cpu (floor 5.6%, counter +5.39%), structops +3.3%, stage-2 +2.46% cpu on
# +0.125% fewer instructions, and it makes stage-1 0.20% FASTER.
trunc32|1|pays on both workloads and costs nothing: divmod +23.2% cpu, stage-2 +2.46%, stage-1 0.20% faster
# builtin-copysign is inert on the self-host -- its stage-1 object is byte

# --- rung 1: the math rows, promoted back after the lowering was fixed
#
# builtin-math sat at rung 10 because one knob carried two lowerings and one of
# them was broken: fabs was spilled to the stack, sign-cleared with a BYTE store
# into the middle of it and reloaded whole -- a store-to-load-forwarding stall
# on every call. The demotion was correct about the pessimization and expensive
# about the sqrt inline riding the same knob.
#
# Both halves of that are now fixed. gen_fabs on x86_64 builds the mask in a
# register and clears the sign bit in one instruction, with no memory traffic
# and no branch:
#     pcmpeqd %xmm1,%xmm1 ; psrlq $1,%xmm1 ; andpd %xmm1,%xmm0
# and the fabs lowering is split onto builtin-math-fabs so it is credited and
# demoted on its own reading rather than the sqrt inline's.
#
# Re-measured with the fixed lowering, N=9 interleaved pairs, layout floors
# taken the same way (padding TU linked ahead of the unchanged kernel, 6
# paddings): mathfun 0.67%, branchy 0.53%, nbody 1.18%.
#
#   builtin-math-fabs   mathfun -27.3% cpu (152.5ms -> 110.4ms) and branchy
#                       -0.85%, counters agreeing at -10.79% and -2.22%. On the
#                       broken lowering the same fold read +85.7% on mathfun and
#                       +47.0% on branchy while retiring FEWER instructions --
#                       the store-forwarding signature, and the reason the row
#                       was demoted.
#   builtin-math        nbody -10.5% cpu (334.9ms -> 299.8ms), counter -4.98%.
#   builtin-math-prepass  carries all of nbody's win: with the prepass off and
#                       builtin-math on, nbody reads +0.15%, inside its floor.
#
# The three rows together cost 0.19% of stage-1 self-compile instructions and
# nothing the clock can see (stage-1 floor 0.55%). No other kernel's object
# changes: of the 17, only nbody, branchy and mathfun move an instruction, so
# every other time delta at -O2 is layout.
#
# The rung is 1 rather than 2 on the rule that a lowering which introduces
# neither a loop nor a nested call does not need its own -O1 measurement to
# earn -O1. Both of these REMOVE a call and leave three straight-line SSE
