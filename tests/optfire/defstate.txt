# <name>|<olevel>|<gate flag>|<on|off>[|<env>]   asserts the gate's DEFAULT state
# Locks the "flipped default-on at -O2" claims in the ungate campaign, which
# differ mode cannot check because it forces the gate on both sides.

divmagic|-O2|divmagic|on

# argfwd's GATE defaults on (o4 || optimize>=2) but the pass is INERT: it lives
# in the replay-time graft path, disabled while MCC_AST_INLINE_PASS is on, which
# it is from -O2. So toggling it changes nothing and this asserts "off" as a
# TRIPWIRE -- if the graft-path guard is ever fixed this cell fails and should
# be flipped to "on". arg-forward sits at rung 4, so -O2 would read "off"
# for the boring reason that the row is not on the ladder; the cell reads at
# -O4, where the gate IS on by default and the pass is still inert.
argfwd|-O4|arg-forward|off
# The four rungs that came off the in-development ladder onto a settled level.
optslice|-O3|opt-slice|off
optslice_below|-O2|opt-slice|off
# fmov-imm lowers a float constant to an FMOV immediate instead of a literal
# pool load; ast_fmov_imm_env is compiled to 0 off arm64, so the gate cannot
# fire anywhere else and the case is registered on arm64 only.
fmov_imm|-O1|fmov-imm|on
#
# --- the rows the CPU-TIME re-derivation moved off the shipped ladder
#
# Each pins BOTH sides of its new boundary, because a single row passes at any
# level at or below the one it names: the -O3 row says the pass is gone from
# the top of the shipped ladder, and the -O4 row says it is still there and
# has not been silently deleted. tests/optfire/leveltime.tsv carries the
# measurement each move was made on; -O4 is where every one of them now lives,
# because the rungs 10-12 they were parked on were consolidated onto it.
#
# Five rows carry only the "off at -O3" half. Their gate IS default-on at the
# rung, but the object stops moving there: a rung turns on every row parked on
# it at once, and one of the others already produces the same lowering on that
# source, so -fno-<gate> emits the same bytes. The "still fires where parked"
# half is carried for those by the counter cells in levels.txt, which read the
# pass firing rather than the emitted bytes and are not masked -- ltemp, pre,
# reassoc and range each assert ON at -O4 there. sethi-ullman-leaf has
# no counter of its own and is covered by tests/optfire/differs_sub.txt.
ltemp_below|-O3|tree-loop-im|off
pre_below|-O3|tree-pre|off
reassoc_below|-O3|tree-reassoc|off
sethi_leaf_below|-O3|sethi-ullman-leaf|off
narrow_elim|-O4|narrow-elim|on
narrow_elim_below|-O3|narrow-elim|off
spill_share|-O4|spill-share|on
spill_share_below|-O3|spill-share|off
vlat|-O4|loop-vlat|on
vlat_below|-O3|loop-vlat|off
# promote-leaf-callee is MCC_OPTD_DEV: +3,525 B of .text across 1,937 programs
# for no measured gain, so a shipped build keeps it off and the pair below reads
# that as the default. Its recorded rung is still 10, but -O10 is an ERROR
# without MCC_DEV now that nothing ungated lives above -O4, so the shipped half
# reads at -O4 -- the highest level a shipped build has -- and the _dev row keeps
# rung 10 under MCC_DEV=1, which is what un-gating has to restore.
promo_leaf_callee|-O4|promote-leaf-callee|off
promo_leaf_callee_dev|-O10|promote-leaf-callee|on|MCC_DEV=1
promo_leaf_callee_below|-O3|promote-leaf-callee|off

# if-conversion-abs joined this block 2026-08-13, and it is the first row here
# moved on an INSTRUCTION-COUNT argument rather than a CPU-time one, so read the
# note in levelpins.txt before treating it as one of the rungs above. The pair

#
# --- the three math rows, back on the shipped ladder at -O1
#
# builtin-math was demoted to rung 10 because one knob carried two lowerings
# and one of them was a pessimization. The fabs lowering is fixed (andpd
# against a register-held mask, x86_64-gen.c) and split onto its own row.
# Neither lowering emits a loop or a call -- each REMOVES a call and leaves
# three straight-line SSE instructions -- so they sit at -O1, and there is no
# shipped level below that to assert the off-half against: at -O0 the AST
# optimizer does not run at all, so -fno-<gate> is vacuously identical there.
math_fabs|-O1|builtin-math-fabs|on
math_sqrt|-O1|builtin-math|on
math_prepass|-O1|builtin-math-prepass|on
#
# --- differ-only gates: the off-side of their default-activation rung
#
# differs.txt forces these gates on both sides, so it proves the pass CAN fire
# but never pins the rung where it turns on BY DEFAULT. Each pair below is the
# standard both-sides shape on the differ's own source, which is forceable one
# rung under (so the off-half is a live tripwire, not vacuous): the on row says
# default-on at the rung, the _below row says default-off one rung under and
