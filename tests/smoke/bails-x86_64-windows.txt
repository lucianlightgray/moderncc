# SMK_TARGET_KEY; a host with no keyed bank of its own falls back to
# tests/smoke/bails.txt, which is the x86_64-linux bank and stays untouched.
#
# Regenerate in this order, then restore this header by hand:
#   smokerun --bank tests/smoke/bails-x86_64-windows.txt --rebank \
#       --min-cases 12800000 --min-passes 150 --min-strats 20
#   smokerun ... --divergence   --rebank
#   smokerun ... --slice-census --rebank
#   smokerun ... --device --min-cases 500000 --rebank
#   smokerun ... --strat-dark   --rebank
#
# Taken 2026-08-15 at 723e5f1a+8da0a02a on Windows 10 / MSVC 14.51 host build,
# NVIDIA RTX 2060 (device oracle: cpu-digest == gpu-digest over 798,500 cases,
# 10,581 dispatches).  TWO INDEPENDENT REFERENCES: winlibs GNU gcc 16.1.0
# (vendor/winlibs-mingw-w64-16.1.0-ucrt-x86_64; the mingw preset superbuild
# re-fetches it) and llvm-mingw clang (scoop mingw-mstorsjo-llvm-ucrt).  Do NOT
# substitute scoop's MSVC-target clang: it cannot link the subject (no
# compiler-rt builtins for __extendhfsf2/__mulsc3 etc.), and do NOT use
# mstorsjo's gcc.exe as the gcc reference -- it is clang in a gcc costume and
# collapses every verdict to diverge-one (see
# DETAILS.md#t-win-50011-resolved-the-f16-divergence-is-the-banked-one-under-a-new-name).
#
# Every row is a triaged finding, not a tolerance.  The Windows-specific
# classes, each with its anchor:
#
# 1. f80.* / xsweep.*.F80 / fsweep.F80.* diverge-both rows: mcc's win32
#    long double is the MSVC model (64-bit binary64); both mingw references
#    use the 80-bit x87 extended model.  One ABI-model difference, hundreds of
#    rows, visible in the dumps as binary64 bit patterns against x87 ones.
#    Deliberate MSVC-conformance, not a defect.
# 2. F16 evaluation-format + NaN-payload rows: the same divergence bails.txt
#    banks on Linux (its header's "140 evaluation-format + 20 NaN sign/payload")
#    -- mcc evaluates F16 chains in float with one final truncation, the
#    references round per-op.  DETAILS.md#t-win-50011-....
# 3. O13 strat-dark rows incl. strat-dark:bfold: data-model darkness -- the
#    subject's bfold/narrow shapes are 64-bit-`long` shapes that do not exist
#    under LLP64; tree-sra/tree-sroa are MCC_OPTD_OFF everywhere.
#    DETAILS.md#t-win-50012-resolved-two-universal-dark-rows-two-data-model-dark-rows.
# 4. O* slice-refused counts: the same counters as the Linux bank at Windows
#    magnitudes (no-static-type 836 vs Linux's 515 at -O4) -- the LLP64 subject
#    produces a different refusal population, counted, not tolerated.
# 5. UB divergence rows (shl.*, neg/abs INT_MIN, signed-overflow classes):
#    mirror the Linux bank's UB classes; where the references disagree with
#    each other the row is diverge-refs, exactly as on Linux.
#
# JIT scope: embed-JIT now links (T-win-50021 s1) + swaps + is observable on PE
# (T-win-50021 s2a fd-shim + the kernel32 swap-diagnostic emit) -- so its honest
# bail categories are banked here as the comment above always instructed ("banked
# when that lands").  jit-not-baked:signature is the population the JIT declines
# for signature reasons (wide/complex args), same class as the Linux bank.
