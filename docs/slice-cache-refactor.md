Refactoring mcc's optimizer from whole-function to a growing leaf-first **rolling window of AST slices** with a subtree-hash-keyed cache. Goals: cross-function/incremental memoization reuse, sharper `-O≥4` search, and **AOT at `-O4+` (JIT off) querying + emitting slices a prior JIT run benchmark-proved** — the shared substrate is the on-disk memo. Codegen may change if measurably better (validated by exec/diff/abidiff/selfhost, not byte-identity).

**Load-bearing decision — slice identity is CONTEXT-FREE (normalized-kernel-hash alone), not chained with enclosing scope.** Forced by the JIT→AOT reuse requirement: a fresh AOT compile must hit a slice a different function/TU optimized under the JIT, and identity must survive "inlining and other layers applied to the same nodes." Dependency path lives in a *separate* locator (for hot-patch), never in the identity. Safe because a gate-config cache value is correct under any collision (worst case: suboptimal passes, never miscompile); per-reuse `ast_slice_equiv`/`certifiable` soundness gate is only needed once actual variants are spliced (final phase).

Aligns with `docs/TODO.md` §26 items 14 (node-identity-stable splice) + 15 (hierarchical hashes); generalizes the existing `jit_graduated_find` seam (mccast.c, currently per-function + `#ifdef MCC_EMBED_JIT`).

**Phases** (each additive, gated, off ⇒ byte-identical): 1 identity ✓ · 2 growing-window populate ✓ · 3 disk JIT↔AOT bridge ✓ · 4 JIT graduation ✓ · 5 hot-patch primitives (first gated increment) ✓. Full status + deferrals now in docs/TODO.md ("Slice cache" section). All uncommitted.

**Phase 5 DONE (first increment):** `ast_slice_splice` (node-stable in-arena replace: live indices outside the replaced subtree keep index+fields; site slot reused as new root; old descendants orphaned, no compaction — the roadmap-14 primitive), `ast_slice_locate` (identity→all sites, roadmap-15 locator half), `ast_slice_promote_static` (static-cost keep/reject = AOT arm of benchmark-gated promotion) — all non-INTERNAL, declared in mccast.h outside the EMBED_JIT guard, asttool-tested (`ast/slice_splice`, `ast/slice_locate`). Wired ONLY into JIT recompile-from-scratch (`mccjit_slice_hotpatch` in `mccjit_recompile_common`), gated additionally by `MCC_AST_SLICE_SPLICE`. **NOT** wired into AOT in-place emit (would desync `ast_locrec`/`ast_fconst`/reloc cursors). Deferrals (in TODO): a productive isolated per-slice optimizer (today `ast_jit_fold_consts` finds nothing new so gate REJECTs — KEEP→splice is unit-proven not live-e2e), per-slice `mccjit_bench_pair` runtime arm, hierarchical-hash upstream propagation, JIT/AOT arena-normalization alignment (P4 caveat). Validated: asttool 747, AOT byte-identical off/on/+splice, jit 48/48 (default+splice-on), exec 297/297.

**Phase 4 DONE:** JIT writes benchmark-proven gate configs into the same store, marked PROVEN. `AstSliceMemo.proven` packed into a spare bit (bit32 of the refcount word; no MAGIC bump; legacy files load as all-static). `ast_slice_merge_one` (proven overrides static, never clobbered back; refcounts sum); probe ranks `(proven desc, size desc)` so proven wins. Near-match path deliberately NOT hooked (its proof is a const-correction table, not a gate config). Validated: AOT byte-identical off & on-empty (write never fires without JIT — AOT run wrote 24 records / 0 proven); jit/ 48/48; exec 297/297; asttool 712 (+21 `slice_graduate`). **CAVEAT (real limitation):** the JIT recompiles from a differently-normalized arena than AOT, so JIT-written proven idents don't always match AOT-shaped idents → cross-mode proven hits aren't guaranteed in practice yet. Identity alignment across JIT/AOT arenas is the gap for P5/future work; the write+prefer mechanism itself is correct + tested.
